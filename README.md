# TwinFiles

轻量的原生 macOS 双栏文件管理器，使用 Swift 和 AppKit 开发，零第三方依赖。通过左右两栏浏览目录、复制和移动文件，支持路径编辑、目录收藏和 Quick Look 预览。

## 功能概览

- **双栏浏览**：两栏独立导航、前进和后退，支持多选；蓝色标题标识当前操作栏。
- **路径复制与编辑**：单击路径栏复制当前目录的完整路径，同时选中路径进入编辑；输入新路径后按回车跳转。
- **终端快捷入口**：点击任一栏路径右侧的终端按钮，在 macOS 自带的“终端”（Terminal.app）中新建窗口并进入该栏当前目录；支持空格、中文等目录名称。
- **文件路径复制**：右键文件或文件夹，选择“复制完整路径”；多选时每行一个路径。
- **文件名复制**：右键选择“复制文件名（含扩展名）”，保留完整名称及后缀；支持文件夹和多选，多选时每行一个名称。
- **文件管理**：复制、移动、重命名、新建文件夹、移到废纸篓，支持剪贴板和跨栏拖放。
- **筛选与排序**：按名称、文件类型和后缀组合筛选，支持名称、大小和修改时间排序，文件夹始终优先。
- **常用位置与收藏**：快速访问个人目录、桌面、下载、文稿、应用程序和已挂载磁盘；收藏在两栏共享并持久保存。
- **系统集成**：Quick Look 快速预览、Finder 定位、使用默认应用打开文件，应用程序包直接启动。
- **状态恢复**：自动监听目录变化，保存窗口位置、两栏目录和隐藏文件显示设置。

## 环境要求

- macOS 13 或更高版本。
- 从源码构建需要支持 Swift 5.10 或更高版本的 Xcode / Swift 工具链。
- 无需安装第三方依赖。

## 下载安装

前往 [GitHub Releases](https://github.com/fangqi179/TwinFiles/releases/latest) 下载新版应用：

- Apple Silicon（M 系列芯片）：选择 `arm64.zip`。
- Intel Mac：选择 `x86_64.zip`。

解压后将 `TwinFiles.app` 拖入“应用程序”。应用采用 ad-hoc 签名，未经过 Apple 公证；首次打开可能需要在系统设置的“隐私与安全性”中允许。每个版本均附带 `SHA256SUMS.txt` 校验文件。

## 构建与运行

在项目根目录执行：

```sh
zsh scripts/build-app.sh
open dist/TwinFiles.app
```

构建脚本会编译 Release 版本、生成图标、组装应用并执行本机 ad-hoc 签名，输出为 `dist/TwinFiles.app`。可将应用拖入“应用程序”目录使用。

构建无需 Apple 开发者账号；当前应用未做 Apple 公证。构建产物面向本机架构，不是通用二进制包。

## 使用指南

### 浏览目录与编辑路径

1. 点击任一栏激活它，双击或回车打开所选文件或文件夹。
2. 单击路径栏，将当前目录的完整路径复制到剪贴板，并进入路径编辑状态。
3. 直接输入新路径并按回车跳转，例如 `~/Downloads`、`/Applications` 或相对路径 `../`。按 Esc 退出编辑。

也可使用 `⌘L` 直接编辑路径，或使用 `⌘⇧G` 打开系统目录选择器。路径显示即使被截断，复制的仍是完整路径；复制路径会替换剪贴板中的原内容。

### 复制与移动

选中文件后，点击标题栏按钮或通过右键菜单复制、移动到另一栏。也可使用 `⌘C` / `⌘V` 复制粘贴，或先 `⌘X`、再到目标目录 `⌘V` 移动。

拖放默认复制，按住 `⌘` 拖放移动。目标可以是对侧目录的空白区域，也可以是子文件夹所在行。

右键菜单还提供“复制文件名（含扩展名）”“复制完整路径”“快速预览”“在 Finder 中显示”等操作。复制文件名只包含名称和后缀，例如 `报告.pdf`、`archive.tar.gz`；复制完整路径则包含所在目录。两者均支持多选，以换行分隔。

### 筛选、排序与收藏

- 名称筛选只作用于当前目录，不递归搜索子目录。
- 底部可选择文件类型和后缀，或输入 `jpg, png`、`*.jpg; .png` 等多个后缀，不区分大小写。
- 名称、类型与后缀筛选组合生效；类型和后缀筛选保留文件夹，方便继续导航。
- 两栏筛选互不影响，切换目录保留底部筛选；底部圆圈叉号按钮清除类型和后缀筛选。
- 点击列表列标题切换排序；升序和降序均保持文件夹在上方。
- 点击每栏左上角文件夹按钮，选择“收藏当前目录”；通过“我的收藏”跳转，通过“移除收藏”管理列表。移除收藏不会删除目录。
- 标题栏眼睛按钮或 `⌘⇧.` 同时切换两栏的隐藏项目显示。

## 快捷键

以下文件操作快捷键用于文件列表；编辑路径或筛选文字时，常规剪切、复制和粘贴作用于文字。

| 快捷键 | 功能 |
| --- | --- |
| Tab（文件列表中）/ Ctrl+Tab | 切换分栏 |
| 回车 / ⌘O | 打开所选项目 |
| ⌘↑ / Delete（文件列表中） | 上级目录 |
| ⌘[ / ⌘] | 后退 / 前进 |
| ⌘L | 编辑路径 |
| ⌘⇧G | 选择目录 |
| ⌘F | 筛选当前目录 |
| ⌘R | 刷新当前栏 |
| ⌘⇧. | 显示或隐藏隐藏项目 |
| 空格 / ⌘Y | Quick Look 预览 |
| ⌘⌥R | 在 Finder 中显示 |
| ⌘⇧C / F5 | 复制到另一栏 |
| ⌘⇧M / F6 | 移动到另一栏 |
| ⌘C / ⌘V | 复制 / 粘贴 |
| ⌘X，随后 ⌘V | 移动文件 |
| ⌘⌥V | 将剪贴板文件移动到当前栏 |
| ⌘A | 全选 |
| ⌘⇧N | 新建文件夹 |
| ⌘⇧R | 重命名一个所选项目 |
| ⌘⌫ | 移到废纸篓，执行前确认 |
| ⌘= | 当前栏打开另一栏的目录 |

部分 Mac 需要同时按住 Fn 才能使用功能键。

## 文件操作规则与限制

- 同名项目自动生成新名称，例如 `报告 副本 2.txt`，保留原文件，不合并覆盖目录。
- 文件夹不能复制或移动到自身及其子目录；移动到原目录不执行操作。
- 批量操作逐项执行，失败后继续处理后续项目，并汇总错误。“停止后续项目”会等待当前项目完成后停止；操作期间阻止退出。
- 文件操作没有全局撤销；废纸篓中的项目请通过 Finder 恢复。
- 目录枚举、筛选、排序及批量文件操作在后台执行；不递归统计文件夹大小，支持浏览目录符号链接。
- 访问桌面、文稿、下载或外接卷时，macOS 可能请求授权；无访问权限时显示系统错误。
- 当前不提供递归搜索、目录同步、文件内容比较、Finder 标签、图库或 iCloud 状态管理。Quick Look 能力取决于系统及已安装的预览扩展。

## 开发与测试

可在 Xcode 中打开 `Package.swift`，或执行开发构建：

```sh
swift build
```

使用仓库内缓存运行 XCTest：

```sh
CLANG_MODULE_CACHE_PATH="$PWD/.build/clang-cache" \
SWIFTPM_MODULECACHE_OVERRIDE="$PWD/.build/module-cache" \
swift test --disable-sandbox --cache-path "$PWD/.build/cache" \
  --config-path "$PWD/.build/config" --security-path "$PWD/.build/security"
```

测试使用隔离的临时目录，覆盖复制与移动、同名保留、防递归、符号链接、隐藏文件、应用程序包、名称校验、组合筛选及排序。界面改动还需手动验证左右两栏及相关快捷键。

### 项目结构

```text
Sources/TwinFiles/          应用入口、窗口与分栏控制器、文件操作及筛选逻辑
Tests/TwinFilesTests/       文件操作与列表行为的 XCTest 测试
scripts/build-app.sh       Release 构建、应用打包与签名
scripts/make-icon.swift    应用图标生成
Package.swift              Swift Package 配置
Info.plist                 应用元数据
AGENTS.md                  贡献与编码指南
```

`.build/` 和 `dist/` 为已忽略的生成目录，请勿提交。贡献前请阅读 [AGENTS.md](AGENTS.md)，保持现有 Swift 风格和中文界面用语，并在提交说明中记录行为变化与验证结果。

## 同步与自动发布

远程仓库为 `git@github.com:fangqi179/TwinFiles.git`。修改完成后，在项目根目录提交并推送：

```sh
git add Sources Tests scripts Package.swift Info.plist README.md
git commit -m "Describe the change"
git push origin main
```

新增文件或其他配置变更需一并加入提交。每次推送到 `main`，包括文档变更，都会触发 [Build and Release](https://github.com/fangqi179/TwinFiles/actions/workflows/release.yml)：

1. 在 Apple Silicon 和 Intel macOS 环境分别运行测试。
2. 构建、签名并验证两个架构的应用，压缩为 ZIP。
3. 两个架构均成功后，创建 GitHub Release 并上传应用和校验文件。

版本号自动采用 `1.0.<工作流运行编号>`，例如 `v1.0.1`，并写入应用元数据，无需手动打标签。测试或构建失败不会发布；可在 Actions 查看日志并重跑。同一次运行重试时更新同一版本的附件。也可在 Actions 中选择该工作流，在 `main` 分支上点击 **Run workflow** 手动发布。

本地尚未推送的修改不会触发发布。工作流使用 GitHub 自动提供的 `GITHUB_TOKEN`，无需配置个人访问令牌；配置见 [.github/workflows/release.yml](.github/workflows/release.yml)。
